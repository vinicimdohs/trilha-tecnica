# Trilha de Evolução Técnica

Programa de estudos em grupo: do código limpo ao design de sistemas. Encontros semanais de discussão, uma trilha de hard skills que anda junto com os livros e **um projeto individual por participante**, que evolui nível a nível.

- 📘 **[ROADMAP.md](ROADMAP.md)** — o programa completo: níveis, cronograma, requisitos e critérios de saída.
- 📅 **[Nível 1 — semana a semana](nivel-1/README.md)** — guia de cada semana do nível atual.
- 👥 **[PARTICIPANTES.md](PARTICIPANTES.md)** — quem está na trilha e o link do projeto de cada um.

> **Nível atual:** Nível 1 — Código Limpo e Vocabulário de Padrões (19/Out/2026 – 19/Fev/2027).

## Como participar

1. **Crie seu projeto do zero** num repositório **público** na sua conta do GitHub. Não há template: a estrutura é livre, desde que cumpra os requisitos do nível no [ROADMAP.md](ROADMAP.md#requisitos-do-projeto).
2. **Entre na trilha por um PR:** faça um fork deste repositório e adicione sua linha em [`PARTICIPANTES.md`](PARTICIPANTES.md) numa branch própria, com commit no padrão [Conventional Commits](https://www.conventionalcommits.org/pt-br/) (ex.: `docs: adiciona fulano aos participantes`). Esse é o primeiro exercício de Git da semana 0.
3. **Acompanhe as [Discussions](../../discussions):** o encontro de cada semana tem uma discussão própria em 📖 Encontros.
4. **Abra sua issue de marco** quando o bloco começar (Issues → New issue → "Checklist do Marco A/B") e vá marcando os itens com links para os PRs que comprovam cada um.

## Onde cada coisa acontece

| Preciso… | Vá em |
|---|---|
| Saber o que ler e praticar nesta semana | [`nivel-1/semanas/`](nivel-1/semanas) |
| Discutir o tema da semana / ler o resumo do encontro | Discussions → 📖 Encontros |
| Tirar uma dúvida | Discussions → ❓ Dúvidas |
| Mostrar uma release ou algo que funcionou | Discussions → 🛠️ Mostre seu projeto |
| Acompanhar meus requisitos de marco | Issues → minha issue de marco |
| Ver o progresso do grupo | Projects → painel da trilha |
| Sugerir mudança no programa | Discussions → 💡 Sugestões (se vingar, vira issue `roadmap` e PR) |
| Pedir review do meu projeto | PR no **meu** repositório, com um colega como reviewer |

## Regras do jogo

- **Repositórios públicos.** Nenhum dado, código, nome de cliente ou informação interna de empresa entra nos projetos, nas issues ou nas discussions. Os domínios são inspirados em problemas reais, mas isolados.
- **Nenhum segredo versionado.** `.env` fica no `.gitignore`; variáveis são documentadas em `.env.example`.
- **O roadmap muda por PR.** Mudanças no programa passam por review e geram nova versão (tag) deste repositório.
- **O calendário não espera por ninguém.** Quem ficou para trás acompanha pelo resumo do encontro e segue com o grupo.

## Versionamento deste repositório

Este repositório segue [SemVer](https://semver.org/lang/pt-BR/), como os projetos dos participantes:
- **MAJOR:** mudança de estrutura do programa (níveis adicionados/removidos, nível concluído).
- **MINOR:** novos conteúdos (semana detalhada, exercício de marco, nível replanejado).
- **PATCH:** correções (datas, links, erros de digitação).

Veja [CONTRIBUTING.md](CONTRIBUTING.md) para o fluxo de mudanças.
